PLANO DE IMPLEMENTAÇÃO — REORGANIZAÇÃO DE ABAS
(categorias fixas + modo tela dividida 50/50)
=================================================================

CONTEXTO
--------
Hoje (ficha.html + ficha.js) as 15 abas vivem numa lista única
(#tabs-nav > #tabs-fixadas + #tabs-mais-menu), com um modo "organizar"
de arrastar-e-soltar (gerenciarLayoutAbas, em ficha.js) pra escolher
quais ficam fixas e quais vão pro menu "Mais". Esse sistema será
REMOVIDO e substituído pelas duas ideias abaixo. Nada de manter os
dois sistemas em paralelo — simplifica o código e a UX.

DECISÕES JÁ TOMADAS (não reabrir)
----------------------------------
- Categorias FIXAS (não customizáveis pelo jogador). Resolve o
  problema de raiz em vez de trocar uma customização frágil por outra.
- Split screen: SEMPRE 50/50, sem divisor arrastável. Cada metade rola
  o próprio conteúdo de forma independente.
- Split screen é um MODO OPCIONAL, desligado por padrão, com botão
  próprio pra ligar/desligar.
- Preferências de layout (categoria/aba aberta, split ligado, o que tá
  em cima/embaixo) são salvas por APARELHO (localStorage), igual já é
  hoje — não vão pra ficha/Firebase.


PARTE 1 — CATEGORIAS
=====================

  JOGO           Combate, Saúde, Veículos, Cenário

1.2 Modelo de dados (JS)
--------------------------
  const CATEGORIAS_ABAS = [
    { chave: "personagem", label: "Personagem", abas: ["perfil","atributos","pericias","vant-desv","especializacoes"] },

1.3 HTML (ficha.html)
-----------------------

PARTE 2 — MODO TELA DIVIDIDA (50/50)
======================================

2.1 Ideia geral
------------------
  Um botão "Tela dividida" (perto de onde ficava o antigo botão
  "Organizar abas") liga um modo onde a tela mostra DUAS instâncias da
  navegação (categoria + sub-aba) empilhadas, cada metade com 50% da
  altura disponível e scroll próprio. As duas metades são
  independentes: metade de cima pode estar em "Jogo > Combate" e a de
  baixo em "Recursos > Inventário" ao mesmo tempo.

2.2 HTML
-----------
  Precisa de DOIS containers de painel em vez de um. Caminho mais
  simples sem duplicar os 15 <section> (que têm IDs/handlers já
  ligados neles): usar UM único conjunto de .tab-panel (como hoje) +
  reparent via JS pro slot certo (cima ou baixo) quando o modo split
  estiver ligado. Ou seja:

  <div class="paineis-area" id="paineis-area">
    <div class="painel-slot" id="slot-principal">
      <!-- os .tab-panel moram aqui por padrão (modo normal) -->
    </div>
    <div class="painel-slot" id="slot-secundario" hidden>
      <!-- só aparece com split ligado; recebe um .tab-panel "emprestado" -->
    </div>
  </div>

  E duas barras de navegação (categoria+abas) completas, uma acima de
  cada slot — a de cima sempre visível, a de baixo (#nav-secundaria)
  só aparece com split ligado.

  IMPORTANTE (risco técnico): mover o MESMO elemento .tab-panel de um
  slot pro outro com appendChild funciona (o DOM só tem um pai por vez),
  mas dois painéis não podem estar VISÍVEIS ao mesmo tempo se forem o
  mesmo elemento. Isso significa que não dá pra ter a mesma aba aberta
  nas duas metades simultaneamente nem reaproveitar o node — cada
  painel só pode estar em um slot de cada vez. Isso é aceitável (não
  faz muito sentido ter "Combate" duas vezes na tela mesmo), mas
  precisa ficar claro: ao escolher no slot de baixo uma aba que já está
  aberta em cima, o de cima perde o conteúdo (ou mostra um aviso
  "Escolha outra aba"). DECISÃO A CONFIRMAR: bloquear a mesma aba nos
  dois slots (mais simples) vs. permitir e aceitar que uma delas fique
  vazia.

2.3 CSS
----------
  .app-body / container principal ganha uma classe .split-ativo que:
    - .paineis-area vira display:flex; flex-direction:column;
      height: [algo tipo calc(100vh - cabeçalho)];
    - .painel-slot { flex: 1 1 50%; overflow-y: auto; min-height: 0; }
      (min-height:0 é essencial em flex column pra o scroll interno
      funcionar em vez de estourar a página)
    - Uma borda/divisor visual fixo entre os slots (sem ser arrastável,
      só uma linha ou barra fininha pra separar visualmente).
  Fora do modo split, .painel-slot#slot-secundario e sua nav ficam
  hidden (comportamento atual, uma coluna só).

2.4 JS
---------
  - Estado: splitAtivo (bool), abaSlotSecundario (string|null).
  - Botão toggle split:
      * Liga: mostra #slot-secundario + #nav-secundaria; abre nele a
        última aba usada no slot secundário (ou uma categoria/aba
        default, ex. sempre abre em "Jogo > Combate" da primeira vez).
      * Desliga: devolve o painel do slot secundário pro slot
        principal (se estava mostrando algo diferente do principal,
        simplesmente esconde; o painel some da tela mas continua no
        DOM dentro do slot principal, sem perder estado interno tipo
        campos preenchidos).
  - abrirAba(dataTab, slot = "principal") — evolução da função do
    Item 1.5, agora recebendo qual slot deve receber o painel. Cuida
    de mover o node .tab-panel certo pro slot certo com appendChild.
  - Persistência (localStorage, por aparelho):
      splitAtivo: true/false
      abaPrincipalAtiva / abaSecundariaAtiva (pra restaurar ao recarregar)


ORDEM DE IMPLEMENTAÇÃO SUGERIDA
==================================
  1. Parte 1 (categorias) sozinha primeiro, testada e funcionando —
     é a base que a Parte 2 depende (abrirAba, CATEGORIAS_ABAS).
  2. Remover de vez o código morto do modo "organizar" (não deixar
     comentado, deletar mesmo — reduz superfície de bugs).
  3. Parte 2 (split): HTML dos dois slots + CSS primeiro, com o botão
     de toggle já funcionando pra só UM painel fixo em cada slot
     (hardcoded), pra validar layout/scroll antes de plugar a lógica
     de troca de aba dinâmica.
  4. Plugar abrirAba(dataTab, slot) de verdade nos dois lados.
  5. Persistência em localStorage por último, depois de validar que a
     navegação em si funciona bem sem ela.

TESTES MANUAIS A FAZER NO FINAL
==================================
  - Trocar categoria mantém a sub-aba lembrada corretamente.
  - Todo `.tab-btn[data-tab="X"]click()` disperso pelo código (ex.:
    botão "Ir pro Inventário" na criação de receita) ainda funciona
    trocando de categoria automaticamente se precisar.
  - Split ligado + desligado não perde o que tava preenchido em campos
    de formulário abertos (ex.: um formulário de item em edição no
    Inventário).
  - Scroll independente de cada metade no celular (tela pequena) e no
    desktop.
  - Reload da página com split ligado restaura estado igual estava.
